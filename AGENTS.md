# Working on Railway Seat Watch

Preserve unrelated work. Keep changes small and verify user-visible behavior. Do not rewrite Git history as part of a code change.

## Source files

Edit `extension/controller.js`, `extension/booking.js`, and `extension/watch.js` for dashboard and booking behavior. `dashboard.html` owns the shared markup and styles. `extension/renderers.js` owns result rendering. The scanner, bridge, background worker, calendar, alerts, and demo runtime are separate source modules.

`extension/content.js`, `extension/ui.js`, and `extension/preview-data.js` are generated by `build-extension.py`. Regenerate them after source edits. Do not edit generated files directly.

The public demo fixture contains fictional trips, fares, and seat counts. Keep captured data in ignored `fixtures/local-*.json` files. Never commit passenger records, session tokens, cookies, credentials, or personal settings.

## Verify a change

Install development tools as described in [CONTRIBUTING.md](CONTRIBUTING.md). Run `npm run check` and check that regeneration leaves no unexpected changes. CI also requires generated files to match their sources.

For a bug, reproduce the failure before fixing it and verify the affected behavior afterward. Prefer behavior tests through the controller, scanner, message handlers, or built ZIP. Keep tests for booking safety, passenger privacy, rate limits, cache reuse, and startup. Avoid tests that only inspect source strings.

Check the browser demo when UI behavior changes. With the demo server running on port 4371, run `npm run screenshot` and inspect `test-results/dashboard.png` for layout issues. Keep the README image untouched; save verification artifacts in ignored `test-results/`. Automated startup and demo checks do not prove that a signed-in D-Ticket session works. Report live browser verification separately, including what was exercised.
